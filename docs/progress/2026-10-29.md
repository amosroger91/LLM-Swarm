## Memory / knowledge worth keeping

- MCP here is `@modelcontextprotocol/server` v2 (`registerTool`, `serveStdio`), not `@modelcontextprotocol/sdk` v1.
- A task satisfies dependents when it is `review`, `revision`, or `done`. Waiting for literal `done` deadlocks job-level review.
- The first revision task id is `revision-2` because the review row is inserted before the id is chosen.
- Windows agent CLIs must be real executables. `.cmd`, `.bat`, and `.ps1` shims are rejected. OpenCode's npm entry is often `opencode.ps1`.
- Worktrees live under `dataDir`, outside the target repository.
- Installed Ollama chat models on this machine are `gemma4:latest`, `qwen3.6:latest`, and `qwen2.5-coder:7b`. `gemma4` answered `/v1/chat/completions` with `response_format: json_object`. `qwen2.5-coder:7b` writes file text, and its unified diffs omit the `+` prefix on added lines.
- A chat worker cannot write the worktree itself. The file landed because the worker returned a unified diff and git apply committed it.
- Every worker worktree is branched from the job base commit, so two tasks that create the same file conflict even when one depends on the other. A one-task plan is the reliable shape for a small site.
- `qwen2.5-coder:7b` often returns a new-file diff for a file that already exists. Writing that diff as file bytes succeeds where `git apply` reports "already exists".
